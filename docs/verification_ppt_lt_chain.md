## Methodology notes

### Independent re-derivation

Every Δv, mass, and trajectory endpoint reported above is
independently re-derived by the verifier:

- **Launch Δv** = `|V1_lambert − v_Earth|` from a fresh Lambert
  solve at the saved `et_launch` and `et_a1_arr`, with the
  `m_revs[0] = 1` revolution branch the solver chose.
- **Per-leg LT trajectory** = forward Sims-Flanagan integration
  using the saved 15-segment throttle profile, starting from
  the pre-leg state (Lambert V1 at Earth for the launch leg,
  asteroid co-orbit velocity for asteroid-to-asteroid legs).
  The integrator is bit-identical to `lowthrust._forward_propagate`
  (same Kepler propagation, same impulsive kick at segment midpoint,
  same Tsiolkovsky mass update).
- **Endpoint check** = compare integrated final state to the target
  asteroid's SPICE state at `et_end`. The re-derived position error
  must match the solver's saved `pos_err_km` (within 5×) and the
  solver's saved `vel_err_kms` (within 5×). Both bounds are met.

### Sources of accepted numerical residuals

- **Position errors at asteroid arrival** (3–24 km across legs):
  inherent residual of Sims-Flanagan with finite segment count
  (15 per leg). Tightening would require more segments or a
  collocation method.
- **Throttle saturation** (segments at |u|=1.000): the engine is
  running at the 0.30 N max during those segments. This is
  expected and within the constraint.

### What this verifier does NOT check

- Power-system mass model (assumes thrust is always available)
- Sun-pointing constraints on the solar array
- Operational margins beyond the hard physical limits
- Trajectory observability / navigation-uncertainty propagation
- Second-order perturbations (J2, n-body) — pure two-body around Sun
- Asteroid arrival trajectory targeting beyond rendezvous-velocity match
